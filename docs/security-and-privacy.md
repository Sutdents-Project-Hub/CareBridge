# 安全、身份與隱私

## 適用原因

本專案 concerns：ai, external-api, personal-data。

## 必須確認

- 身份、角色、允許與拒絕邊界，以及敏感操作的可信任執行端。
- 個資或學生資料的來源、最小蒐集、用途、保存、刪除、去識別與公開展示限制。
- Secrets 只存在本機忽略檔或部署平台，不進入前端、文件、log 或 Git。
- 驗收需涵蓋未登入、越權、錯誤輸入與資料外洩情境。


## 威脅模型與處理原則

| 威脅 | 風險 | 開發要求與驗收 |
|---|---|---|
| 真實長者姓名、身分、病歷或照護細節被輸入 | 隱私與第三方傳送 | 首頁明示請勿輸入真實個資；測試使用虛構案例；只送必要訊息；不要持久保存 |
| API Key 暴露在瀏覽器或 Git | 額度盜用、付費損失 | Key 僅 server-only 環境變數，永遠沒有 NEXT_PUBLIC_ 前綴；不放 log 或 .env.example 真值 |
| 公開匿名網站被大量呼叫 | 耗盡費用或使評審不能試用 | 限制字數、token、逾時、速率、供應商費用上限；部署平台是否支援分散式限流須實測 |
| Prompt injection | 使用者要求覆寫倫理、捏造摘要 | 固定 server-side safety/system 指令；使用者文字一律視為資料；負向案例 C24 |
| LLM 幻覺 | 虛構處置、效果、原因 | 事實欄位先採確認後決定性模板；不確定則待確認；測試 C25–C30 |
| 高風險健康問題 | 延誤求助、越權診斷或調藥 | 不給藥量、處方、診斷；急迫狀況顯示求助真人／當地緊急服務；測試 C19–C23 |
| 多語誤譯 | 英／印尼語風險警語失真 | 原文對照、預設保守警語、人工作語意審核；未經母語者審查不得宣稱已驗證 |
| 模型供應商與託管日誌 | 未預期資料保留 | 部署前查閱供應商/host 的資料政策，關閉不必要的 request body 記錄及第三方 analytics |

### 資料流與保留

- **預設無登入、無 database、無 server-side 聊天紀錄**。訊息只在瀏覽器分頁狀態；重新整理失去對話，是隱私取捨。
- 匯出只能是明確由使用者操作，且在匯出前提供去識別提醒；實驗紀錄只存**虛構**個案。
- 不應在例外堆疊、monitoring、error tracking、access log 或 analytics 中記錄完整 Prompt、API Key、對話內容、家庭通訊資料。
- 真正供應商可能有服務端資料處理，**無法僅因本系統沒有資料庫就宣稱完全不儲存**；目前以 OpenAI Responses API 傳送必要近期訊息，設定 `store: false`。供應商及主機另有資料處理政策，見 [整合說明](integrations.md)。

### 高風險回應設計

遇到突然失去反應、突發單側無力、呼吸異常或其他可能急迫表現，應先提示聯繫**當地緊急服務或合適的醫療人員**；不可延遲求助只與聊天機器人交談。此為介面求助原則，不等同完成急症分類器或臨床檢驗。地區不明時不硬編特定急救號碼。

遇到「藥物應加倍嗎」、「如何控制／欺騙長者」等，避免提供危險處置，改用尊重與求助方向。避免對長者使用貶低語言。高風險範例參照 evaluation-cases.md。

### 驗收與公開透明

- 登入狀態：P0 無帳號；若日後加登入是架構和隱私變更，先取得授權。
- 安全 gate：高風險題不得有嚴重越界，任何失敗都需留負面測試與限制，不以平均分掩蓋。
- 文字聲明：此服務提供日常溝通建議，不能取代專業照護、診斷、藥物處理或緊急救援；未經臨床和印尼語母語完整驗證。
- 不得無授權公開真實長者、照護者、學生的姓名或其對話紀錄。
