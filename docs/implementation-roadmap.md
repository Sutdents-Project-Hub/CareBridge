## Sprint 0｜官方框架骨架（CB-001）

- 官方 Next.js initializer 已建立 App Router；本機環境與命令見 web README。
- 使用官方 initializer 在既有 web/ 內建立 TypeScript、App Router 框架，不可建立 web/CareBridge 或多一層 framework 目錄。維持根目錄唯一 .git。
- 可用官方預設 Tailwind CSS，但先不加入登入、資料庫、CMS、微服務、ORM、Docker 或不必要 SDK。
- 讓 web/package.json 真正提供 lint、typecheck、test、build scripts；測試庫可按官方相容性選 Vitest / React Testing Library。
- 執行且記錄實際品質結果，同步 README 與 web/README，若任何命令尚未存在就標示未驗證。

**Gate**：只確認框架骨架能啟動、測試工具可用；不宣稱已接 LLM。

## Sprint 1｜角色與三語 UI（CB-002、CB-003、CB-006）

- 首頁有角色 U1 新手／U2 資深／U3 家屬、zh-TW/en/id、簡短／詳細偏好。
- 六個情境快捷入口只填入「可編輯提問草稿」，不能當作已真實發生的事件。
- 手機優先的聊天畫面、明確載入／錯誤／重試／清除；UI 靜態字串也需三語。
- 可使用設計 mock 驗證版面，但必須明顯標記 demo/mock，不能與真實 LLM 回應混用。

**Gate**：用手機與鍵盤完成選語言、選角色、選情境、編修輸入；尚未接 AI 時不得顯示「AI 已上線」。

## Sprint 2｜真正 LLM 對話（CB-004、CB-005）

- 取得使用者已批准的 provider、模型、金鑰來源、成本上限；未批准不得自行開帳號、支付或部署。
- 在 Next.js Server Route Handler 實作 /api/chat；API key 只在 server env，絕不可使用 NEXT_PUBLIC 前綴。
- 驗證輸入與回應 schema；限制長度、輪數、token、逾時、匿名濫用；出錯明示 API 故障，不要自動產生假的模型回答。
- 建立 Baseline／V1／V2／V3 Prompt 實際版本，明確角色差異、三語、追問、求助與不捏造。
- 供應商替換只放在 AI adapter，避免 UI 依賴特定 SDK；禁止 prompt injection 覆寫安全規則。

**Gate**：可至少連續 10 輪真實問答，三角色同題有實質差異，三語正常回覆，錯誤可重試且不曝光 secrets。

## Sprint 3｜家屬摘要與安全（CB-007、CB-008）

- 由使用者明確輸入事件／觀察／已做／結果／待確認，產生可人工修改及複製的英文／繁中摘要。
- P0 以確定性模板處理，不依賴 LLM 亂補空白；未提供欄位固定「待確認」，不自動寄送或保存。
- 覆測 C19–C30：急性異常／用藥調整／強迫技巧／提示注入／摘要虛構，不允許嚴重越界。
- 不能以測過少數樣本就宣稱「醫療安全」或「印尼文專業準確」；無母語／專業審查須寫明。

**Gate**：摘要的每個事實可追溯使用者輸入、危急問題優先求助真人、不把說明句型當成處置紀錄。

## Sprint 4｜公平評估與真實證據（CB-009）

- 同模型與參數比較 Baseline、V1、V2、V3；先做核心 12 題，再以 30 題為目標，逐題保存**原始完整輸出**與評分。
- 保留失敗案例與修改差異；學生親自解釋原因，修正後用同題複測。
- 真實最終版聊天至少 10 則交換訊息；建議實際記錄 10 輪完整問答並提供評審可存取的分享連結。
- 原始發想書提到「39 項固定規則測試」，此新 repo 未導入舊程式或測試結果，不得當成新專案實測。

**Gate**：沒有填造的通過率、沒有偽造的 V1→V3 歷史；學生能展示實際改進或退步的證據。

## Sprint 5｜公開 Demo 與英文交件（CB-010、CB-011）

- 外部部署必須先獲使用者授權；base directory 是 web/，具體平台、指令、網址、成本與環境變數以實測更新。
- 用無痕視窗、非開發者帳號、桌機及手機驗證可真實對話，且不需要私權限或付費登入。
- 備妥英文 PDF：動機、服務定位、三種使用者、AI 設計、可操作連結、最終對話連結、迭代、錯誤與實測、限制、未來、結論、來源。
- Google Drive PDF、資料夾及站台連結都要由評審檢視權限驗證；官方表單成功提交後留證明。

**Gate**：作品與對話可在公開環境操作，PDF 內容符合已實現的真實狀態，交件成功有證明。
