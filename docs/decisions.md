# CareBridge｜架構決策與待決議事項

> 2026-11-20 初版。以下是已整理的開發**規劃選擇**；不是平台、模型、成本或測試完成證明。

## ADR-001｜採單一 Next.js Web 架構

- 狀態：已建立本機 Web MVP。
- 原因：WAICY 第 4 賽道重在可操作的專業 LLM 顧問與實驗證據。單一 Web + server API 足夠支援三語、不同角色及聊天，不需為短期競賽新增微服務。
- 採用 Node.js 24 LTS、TypeScript、pnpm、Next.js。
- 不選替代方案的理由：Next.js + NestJS 增加維運與協調；純客製 GPT 難以控制完整三語 UI、資料契約與實驗紀錄。
- 改變架構（獨立 backend/DB）前必須有確切需求及批准。

## ADR-002｜不建立登入或永久儲存

- 狀態：已實作。
- 原因：不必要保存長者照護資訊有隱私風險，也增加評審試用障礙。
- 方案：對話只保存於當前分頁記憶體；不建資料庫或帳號。學生可主動匯出虛構案例的測試紀錄。
- 代價：重整會失去歷史；需主動記錄最後版對話並確保分享連結存在。
- 如果日後要保存資料，先釐清同意、用途、保存期限、刪除、控權與資安。

## ADR-003｜家屬摘要優先確定性模板

- 狀態：已實作。
- 原因：不能把「想試試看」寫成「已做過」，也不能補造結果。
- 做法：事件／觀察／已做／結果／待確認，未知一律待確認；需人工確認才可複製。
- 代價：文字可能不如生成式流暢，但能降低捏造風險；日後若加入 AI 潤稿應要求來源可追溯。

## ADR-004｜先設計 Prompt 迭代，不自行訓練

- 狀態：已實作。
- 原因：第 4 賽道允許既有模型。Specific AI Service + Iterative Development 合占 50 分；公平 Baseline/V1/V2/V3 實驗更重要。
- 條件：同模型、同參數、同題，保留原始輸出、失敗、原因與學生修改。
- 限制：供應商採 OpenAI。使用模型、實測與預算尚待確認。

## ADR-005｜外部成本與部署須另行授權

- 狀態：未決議。
- 已授權實作 OpenAI API 串接；實際付費請求、預算、部署與網域仍待確認。
- 候選是能運行 Next.js server runtime 的平台，Vercel 只是候選，不代表已選或已核實方案。
