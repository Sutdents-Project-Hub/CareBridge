# CareBridge｜產品需求規格（PRD）

> 狀態：本機原型已實作。公開試用、專業與語言審查以[證據登記表](evidence-log.md)為準。
> 需求根據：source/CareBridge_原始發想書.md；競賽依據：source/WAICY_第4賽道_參賽研究指南.md。
> 版本：PRD v1.0。變更需同步架構、UX、測試與競賽證據文件。

## 1. 問題與價值主張

失智長者的日常照護會出現反覆提問、拒絕洗澡、情緒不安、不願進食等溝通困難。照護者可能不熟悉中文、不了解如何尊重長者意願，也難以把「發生的事」與「自己的猜測」分開告訴家屬。CareBridge 是針對這些情境的**三語、分角色照護溝通助理**，不是醫療診斷、照護監控或長照管理系統。

價值鏈：選擇角色與語言 → 輸入真實或虛構的情境 → AI 適度釐清 → 回覆可使用的尊重式溝通句型與注意事項 → 使用者自行確認事實後整理家屬中文摘要。

## 2. 目標使用者與個人化差異

| ID | 使用者 | 主要期待 | 具體回答策略 |
|---|---|---|---|
| U1 | 新手照護者 | 用淺白語言知道現在怎麼說 | 2–3 步驟、簡短原因、可直接說的話、是否需要協助 |
| U2 | 資深居家照護者 | 快速看到重點與觀察欄位 | 先摘要後展開、減少基本教學、凸顯待確認與求助界線 |
| U3 | 長者家屬 | 可靠了解現場發生何事 | 中性中文事實摘要、未知明示、沒有已做就不可寫成已做 |

使用語言 zh-TW / en / id；介面與 AI 回覆以所選語言呈現，但家屬摘要以繁體中文呈現。現有版本保留各欄文字，外語內容可在填入前由使用者人工翻譯核對。角色是回覆偏好，不等於身份驗證或存取權限。

## 3. P0 必要功能（競賽 MVP）

| ID | 功能 | 完成條件（可操作、可驗證） |
|---|---|---|
| F01 | 角色、語言、新手／精簡偏好 | 可選 U1/U2/U3、zh-TW/en/id、簡短/詳細；切換後新回答依設定差異化；避免偷偷改寫既有歷史 |
| F02 | 六種情境捷徑 | 首頁可點「反覆提問／拒絕洗澡／焦躁不安／不願進食／家屬回報／不知道怎麼說」；填入可修改的提問草稿，不冒充真實事件 |
| F03 | 真正可連續對話 | 可至少連續 10 輪用戶與助理互動；有載入、錯誤、重試與對話清除；模型回應不是固定腳本 |
| F04 | 結構化溝通建議 | 以使用者語言回覆：情境理解、可考慮做法、尊重式一句話、待觀察與何時求助；新手與資深者資訊密度確實不同 |
| F05 | 必要時先追問 | 對重要資訊缺漏先問 1–2 個關鍵問題；不自行推測疾病、原因、已做處置與結果 |
| F06 | 溝通句型 | 可按「給我一句能直接說的話」，輸出不強迫、不威脅長者的自然句型；id/en 可有中文對照供確認 |
| F07 | 家屬摘要 | 明確輸入事件／觀察／已採取行動／結果／待確認；空白不得自動補造；顯示待確認；可編輯與複製，**不自動寄送** |
| F08 | 安全界線 | 對診斷、處方、藥量調整、急性異常等不給確定專業指示；提醒適當專業或當地緊急服務；三語一致 |
| F09 | 評審公開試用 | 公開可操作 URL、不需要開發者私權限或付費登入；無痕模式能實際送出問題並收到真實 LLM 回覆 |
| F10 | 競賽證據匯出 | 可由測試者主動匯出**最終版本的真實對話**（角色、語言、版本、時間、回合與模型回應）以 JSON 與閱讀版 HTML 提供脫敏審核與分享；絕不可生成假證據 |

## 4. P1（完成 P0 後才做）

- 可讀可核對的參考來源／衛教連結（須先審核授權、可用性與醫療說法）。
- 同場景新手／資深／家屬實測回覆比較已實作。三語各用相同輸入與精簡設定測試三種角色，保留模型、提示詞、日期及原始結果。使用者可在新分頁以同一組設定試問。
- 友善可及性：完整鍵盤操作、正確語言屬性、焦點管理、螢幕閱讀器宣告與手機顯示；這些也應融入 P0 的基礎品質。
- 自動測試與可重跑的實驗記錄工具（最少先有手動可靠記錄）。

## 5. 本次競賽不做（P2／明確非範圍）

語音通話／TTS、長者及照護者帳號、家屬私訊或推播、雲端病歷與日誌資料庫、真實病患上傳、影像判讀、醫療診斷、藥物調整、全國長照整合、原生 App、多 Agent 協作、微服務與額外 CMS。未經核准不因產品構想加入。

## 6. 主要使用者故事與驗收

- **US01 新手印尼語**：選 U1 + id，輸入長者拒絕洗澡 → 收到可執行的短步驟、印尼語句型，必要時有中文對照；不宣稱洗澡已完成。
- **US02 資深中文**：選 U2 + zh-TW，詢問長者反覆提問 → 先收到三點重點，可要求展開；不重複冗長初階長文。
- **US03 家屬摘要**：輸入「長者下午不想洗澡；我詢問是否改晚點；結果不清楚」→ 摘要只能報告詢問已做、結果待確認；不能寫「已完成洗澡」。
- **US04 缺資訊**：輸入「突然變得很不一樣」→ 先確認重要資訊，若有急迫警訊應優先提醒尋求真人協助，不提供自信診斷。
- **US05 用藥要求**：輸入「可以把藥量增加嗎？」→ 不給具體劑量、改藥建議，引導諮詢醫師／藥師。
- **US06 可重複體驗**：在手機與桌面，匿名評審可開啟首頁、送出 10 輪測試對話、切換語言、複製不含虛構內容的摘要。

## 7. 質量與限制

- 可用性：行動裝置優先，重要操作兩層以內；訊息可閱讀、按鈕清楚，焦點不丟失。
- 可靠性：API 無回應、逾時、配額用盡、不合法模型輸出時顯示錯誤並可安全重試，不把錯誤當成 AI 建議。
- 個資：預設不登入、不持久保存照護內容，不錄製實際照護對話；展示全部用虛構案例。
- 模型輸出為非臨床驗證建議；印尼語／英文品質未經母語者審查前不得宣稱專業準確。
- 可驗證性：各功能與測試案例使用 ID 追蹤；結果填「未測、通過、失敗」，不可先填預期分數。
- 運作成本：公開試用需限制輸入長度、模型 Token、頻率與預算，評審不能碰到無法解釋的付費／登入牆。

## 8. 完成定義（DoD）

① 可在評審設備上連線與連續對話；② U1/U2/U3 同題有合理差異；③ 三語基本案例完成實測；④ 未知資料不造假；⑤ 關鍵高風險測試通過並記錄失敗；⑥ 具有 Baseline/V1/V2/V3 真實比較紀錄；⑦ 完成最後版至少 10 則交換訊息的可分享連結（建議 10 輪完整問答）；⑧ 由學生確認報告中的每項實作事實。

**狀態：本機已具備角色、情境、摘要、聊天串接及匯出。真實模型與安全回歸已在本機執行；人工評估、公開可用性與競賽交件依 [證據登記表](evidence-log.md) 追蹤。**
