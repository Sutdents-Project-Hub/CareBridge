# 專案範圍與驗收

## 專案摘要

提供繁體中文、英文、印尼文的失智照護日常溝通建議、尊重式句型與經使用者確認的家屬事實摘要（英文或繁體中文）；非醫療診斷或用藥工具。

## 本階段目標

- 階段：競賽／展示
- 本機 Web MVP 已建立，完成第一輪真實模型評估。公開展示與競賽交件仍待完成。

## 範圍

- 三種使用者角色與新手／資深差異化體驗
- 繁中、英文、印尼文對話與中文對照
- 可連續追問的照護情境 AI 顧問
- 尊重長者的溝通句型
- 事實、已做、結果、待確認的家屬摘要草稿與人工確認
- 危險與超出能力時的求助提醒
- 評審可操作的連結、真實聊天紀錄匯出與 Baseline/V1/V2/V3 迭代證據
- 每一項功能需有可展示或可測試的完成條件。

## 當前階段界線與明確非範圍

- **競賽 MVP**具備三角色、三語、OpenAI 對話串接、溝通句型、家屬事實摘要與安全求助。已驗證公開試用的角色入口、對話、摘要與匯出。競賽最終對話待參賽者操作，逐項條件見[交件清單](waicy-submission-todo.md)。
- 本屆明確不做帳號、長者病歷資料庫、雲端長期照護紀錄、推播、語音、原生 App、全科醫療顧問、多 Agent、CMS、RAG 或不必要微服務。
- 安全與必要品質並非「排除的功能」：不診斷、不調藥、不捏造已執行事項、不要求真實個資、三語未審查揭露與公開評審可操作性，皆屬必備條件。
- 未確認的付費帳號、外部 API、資料保留、部署、production 資源與授權，均須依未來明確任務取得必要批准。
- 不因範本建立未使用的 component root、共用套件或基礎設施；專案狀態不得把規劃、模擬與已實作混淆。

## 驗收方式

- 以主要使用流程、錯誤情境、資料結果與實際執行的品質指令驗收。
- 無法自動驗證的項目需記錄人工步驟、預期結果與限制。

## 未決定事項

- 指導者與學生的實際分工、英文姓名與參賽隊伍資訊待補
- 正式公開時的 OpenAI 額度與部署環境穩定性待驗
- 匿名試用的長期額度控管與正式交件驗收待確認
- 照護內容審稿人、印尼語母語審查與授權素材來源尚未確認
- 主辦第 4 賽道的登入可用性、18 歲參賽等仍須依實際隊伍狀況核對

## 假設

- 優先單一 Next.js Web 服務，使用 server-side Route Handlers 呼叫外部 LLM，避免為短期競賽額外建 NestJS/DB
- 本機 Web MVP 採 Node.js 24 LTS、TypeScript、pnpm、Next.js
- 長期儲存、登入、語音、原生 App、RAG、管理後台與自動傳訊均非 MVP
- 評審展示只用虛構資料，聊天內容匯出需人工同意與脫敏
- 公開試用已上線於 [Vercel Hobby](https://carebridge-neon.vercel.app)，正式環境模型回覆經匿名操作確認。
