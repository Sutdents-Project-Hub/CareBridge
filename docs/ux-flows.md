# CareBridge｜介面資訊架構與使用流程

> 已在本機 Web 實作照護對話與家屬摘要，採手機優先與三語 UI。照護者使用測試及外語人工審查待進行。

## 導覽與畫面地圖

1. **首頁／入口**：頁首提供照護對話、家屬摘要與語言。首頁下方直接放輸入區及六個情境；手機隱藏情境照片，優先顯示對話操作。
2. **對話頁**：收合的對話設定顯示目前角色與回答長度，展開可調整。設定套用到下一則回覆。對話可切換語言，並顯示模型回覆區塊（我理解的情況／可嘗試做法／一句可說的話／待確認／何時求助）、追問輸入與快捷按鈕。
3. **句型卡片**：可複製的主要語言句子；跨語言顯示中文對照，原語與繁中可各自複製，保留原分行；不提供「保證讓長者服從」的強制語句。
4. **家屬摘要確認**：人工填／改「事件、觀察、已執行、結果、待確認」→ 預覽繁中摘要 → 再次檢查 → 自行複製。未提供欄位一律「待確認」，不得以建議充當行動。
5. **關於／限制**：介紹定位、個資提示、AI 的非醫療界線、公開展示只用虛構資料、遇到危急狀況該找真人。
6. **測試者證據工具**：僅由操作人主動點選「匯出本次對話」；先提醒去識別化，匯出包含版本與訊息順序，可選 JSON 或開啟／列印的閱讀版 HTML，不自動對外發送。

## UX Flow A｜新手照護者

開啟首頁 → 選擇新手照護者 + Bahasa Indonesia → 點「拒絕洗澡」 → 自行編修情境 → 開始對話 → AI 用印尼語提出尊重選擇的溝通方式 → 點「一句能直接說的話」 → 對照中文核對 → 可繼續追問 → 如需回報，轉至家屬摘要確認頁，明確填入真正發生的事。

**驗收**：多語語意一致、句子自然但未經母語審查則標示、沒有把建議當既成事實。

## UX Flow B｜資深照護者

首頁 U2 + 繁中 + 精簡 → 輸入長者反覆問用餐時間 → AI 以三點回應 → 點「更詳細」展開 → 必要時列待觀察事項 → 點「整理家屬摘要」轉為記錄欄位。

**驗收**：資訊密度確實小於新手模式、不省略高風險提醒、不自動填寫未發生處置。

## UX Flow C｜家屬

首頁 U3 → 選「家屬回報」 → 貼上去識別的零碎事件 → 開啟家屬摘要 → 使用者逐欄填寫並核對事實 → 顯示繁中回報摘要 → 點複製後自行分享。

**驗收**：觀察、推測、實作結果分離；空白欄位不臆測。

## 主要畫面組件

| 組件 | 功能與注意 |
|---|---|
| ProfileSelector | U1/U2/U3，角色切換套用於後續回答，過往訊息保留原語言 |
| LanguageSwitcher | zh-TW/en/id；對應完整 UI 字串詞典；外語句型可顯示繁中對照 |
| ScenarioChips | 六個固定示例只填草稿，不會自動送出 |
| ChatComposer | 多行文字、送出、字數提示、保留失敗草稿與重試 |
| AdvisorMessage | 將模型結構化結果分區，支援複製、鍵盤焦點、讀屏 |
| PhraseCard | 主要語言句型及可選繁中核對 |
| FactEditor | 五欄可編輯資料，來源與建議分離；未提供標成待確認 |
| SummaryPreview | 使用者確認後才允許複製，不自動傳訊 |
| ErrorNotice | 清楚顯示逾時／模型不可用／過度頻繁／輸入過長 |
| PrivacyReminder | 不輸入真實長者個資、診斷與治療資訊 |

## 狀態機

- landing → composing → loading → answered / clarification / escalation / error。
- answered → follow-up → loading 或 → fact-review → summary-preview → confirmed → copy/export。
- escalation 可繼續提供安全的人員求助資訊，但不得被一般句型按鈕覆蓋。
- 角色與語言設定從下一則回覆生效，歷史訊息保留當時語言；移到摘要再回來時，從最新一輪接續。手機對話使用頁面捲動。
- 發生連線問題：保留本地文字輸入，可主動重試，並顯示靜態緊急求助提醒。

## 多語言與無障礙規則

- UI 所有靜態訊息、標籤、錯誤提示與安全警語都需有三語版本；避免只翻譯 LLM 回覆卻保留中文操作介面。
- 使用 lang=\"zh-Hant\" / \"en\" / \"id\"（依 UI locale）協助螢幕閱讀器；異語句子局部使用正確 lang。
- 手機 320px 起不水平溢出；文字大小可放大；符合基本 WCAG 可辨識對比；焦點可見，鍵盤全程可用。
- 危險提醒以清晰文字區塊呈現，不只靠紅色或 Emoji；不要用 UI 動畫稀釋緊急性。
- 延遲時提供明確狀態，失敗後可重試；新回答以適當 aria-live 協助讀屏但避免反覆朗讀整頁。
- 先使用中性、柔和、非醫療機構冒認的視覺語言；不使用真人長者照片或有辨識性的案例作展示。

## Demo 腳本（4 分鐘內示意，非官方限定時長）

1. 20 秒：一句話介紹 CareBridge 解決溝通與家屬事實摘要，而非醫療診斷。
2. 70 秒：U1 + 印尼語拒絕洗澡 → 句型 + 中文核對。
3. 60 秒：同題切換 U2 / U3，展示個人化差異；避免把不同模型輸出當為固定保證。
4. 60 秒：摘要表單只輸入已知、故意留空結果 → 看見「待確認」而非虛構成功。
5. 40 秒：詢問用藥調整 → 展示求助界線，最後打開版本比較與真實實驗證據。

**展示準備**：公開站台有網路與 API 配額、備用測試情境；預錄畫面只作網路故障備案，不能取代官方要求可操作的連結。

網站沿用 Lesson Plan 的白底、淡藍與墨藍。對話卡在桌面將編寫與情境捷徑並排，手機將輸入框置於雙欄情境選項之前，角色與回答長度預設收合。摘要並排顯示輸入與預覽，窄螢幕先填寫再往下核對；修改欄位會取消已確認狀態。情境照片為專案生成的虛構場景。
